# Three-resource transition monoid

This repository is the focused home for an exact finite transition monoid generated by opening and closing three independent resources.

The system has:

- **9 semantic states**: the 8 open/closed resource configurations plus one trap state;
- **6 generators**: `open0`, `close0`, `open1`, `close1`, `open2`, `close2`;
- summaries consisting of a state transition together with a 3-component additive delta;
- composition by ordinary state-map composition with the downstream delta pulled back through the first state map.

## Exact census

Independent regeneration from the six generator summaries gives:

- **3,536 distinct summaries**;
- minimum index width: **12 bits**;
- maximum shortest representative length / Cayley-graph radius from the identity: **8**;
- exact depth histogram:

```text
0:    1
1:    6
2:   36
3:  145
4:  432
5:  876
6: 1088
7:  776
8:  176
```

The counts sum to 3,536.

## Stronger than the old Lean label

The historical Lean port stored `3536` as a constant; that did **not** kernel-certify the census. The recovered machine artifact is stronger: `MONOID-CATALOG.json` contains all 3,536 summaries, representatives, and six generator transitions for every element.

More importantly, [`verify_monoid.py`](verify_monoid.py) does not trust that catalog. It starts from only the six one-step generator summaries and recomputes the generated monoid from scratch. It verifies the size, distinctness, reachability, shortest-depth histogram, and diameter/radius claim exactly.

So the 3,536 count no longer rests on an asserted Lean numeral.

## Four-resource comparison

The recovered census also reports the analogous four-resource system at **417,874** summaries with maximum shortest representative length 13. That larger system is retained as comparison data in [`MONOID-CENSUS.json`](MONOID-CENSUS.json); this repository's independently regenerated theorem is the three-resource result.
